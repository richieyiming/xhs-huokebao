# 数据诊断与评论洞察

用于账号复盘、选题迭代、竞品研究和评论区需求挖掘。数据结论必须带平台、时间窗、样本量和置信度；平台规则与健康阈值会变化，不把经验值写成官方标准。

## 一、先建自己的基线

优先取同一账号、同一内容形态最近 20 条以上作品；不足 10 条时标低置信度。

- 保留曝光/播放、点击或封面打开、阅读/完播、点赞、收藏、评论、分享、主页访问、关注、私信、咨询和成交等实际可得指标。
- 每个平台、账号、内容形态分别计算，不把图文、视频和直播混在一起。
- 用中位数作为常态基线，避免一条超级爆款扭曲平均值。
- 爆款和失败内容都与自己的基线比较，不只看绝对数字。

参考异常标签：相对基线 1.5—2 倍为轻度异常，2—5 倍为强异常，5 倍以上为巨大异常。标签只服务内部研究，不冒充平台标准。

## 二、漏斗定位

按“被看见 → 愿意点 → 愿意读 → 愿意互动 → 愿意行动”找问题：

| 症状 | 优先检查 | 下一步实验 |
|---|---|---|
| 曝光低 | 关键词、选题需求、账号定位、合规风险 | 换更明确的需求词和人群场景，先排除违规 |
| 曝光有、点击低 | 封面0.5秒理解、标题具体度、搜索意图 | 一次只改封面或标题，保留对照 |
| 点击有、阅读/完播低 | 前三行、首屏信息、内容兑现速度 | 把结论或痛点前置，删背景铺垫 |
| 收藏高、咨询低 | 内容有用但产品连接弱 | 增加自然的下一步和适配钩子，不硬卖 |
| 评论多、精准咨询少 | 话题太泛或钩子吸错人 | 收窄人群、阶段和问题，换精准扣词 |
| 私信多、成交低 | 钩子与正价产品错位、筛选不足 | 检查线索分级、需求诊断与承接材料 |

每轮只改一个关键变量；同时改标题、封面、正文和钩子，就无法判断真正原因。

## 三、评论区需求挖掘

收集公开评论时保留原话、点赞数、时间和来源；删除重复、纯表情和明显垃圾内容，但保留口语、错别字与情绪词，因为这正是用户语言。

按以下类别标注：

- 问题：还想知道什么
- 痛点/抱怨：具体卡在哪里
- 顾虑/反对：为什么不相信或不行动
- 困惑：哪些表达没有讲明白
- 求推荐/求步骤/问价格：需求与购买信号
- 争议：适合做对比、避坑或矛盾型内容
- 结果反馈：真实使用后的正负体验

聚类时同时标“频次”和“强度”。一条高赞评论仍可能只是个例；多个独立用户反复出现，才进入核心需求词库。引用代表性语言时去掉不必要的用户名及个人信息。

## 四、转为可执行资产

每次复盘至少产出：

1. 保留并复制的内容机制。
2. 本轮唯一要修的漏斗环节。
3. 评论区新增需求词与用户原话。
4. 下一轮 3—5 个选题。
5. 一个单变量测试方案。
6. 需要停止的低效题材或错误钩子。

输出模板：

```text
【范围】账号 / 平台 / 时间窗 / 样本量
【基线】各核心指标中位数
【异常内容】提升倍数 + 原始链接
【漏斗卡点】曝光 / 点击 / 阅读 / 互动 / 行动
【评论洞察】问题 / 痛点 / 顾虑 / 需求信号
【下一轮动作】保留什么、只改什么、停止什么
【置信度】高 / 中 / 低及原因
```
