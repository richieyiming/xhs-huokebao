# _inbox · 新方法论入口

看到新的小红书获客方法、踩坑经验、平台新规则、某行业跑通的打法，**随手把文件丢进这个目录**，然后说一句：

> 「蒸馏这个」 / 「把这个并入小红获客宝」

## 处理规则

| 内容类型 | 归到哪里 |
|---|---|
| 新的获客打法 / 框架 | 蒸馏成方法 → 并入对应 reference（01-15），并在 SKILL.md 路由表补链 |
| 需求拆解 / 量产 / 钩子设计类打法 | 并入 `14-需求拆解与钩子工程.md`（填表裂变 / 需求即组件 / 钩子四档 / 鸡蛋要领） |
| 选题生成 / 模板批量 / 维度拆分类打法 | 并入 `15-维度乘法与完形填空模板.md`（维度相乘 / 完形填空 / 对号入座 / 四维度公式 / 行业样本） |
| 新的违规词 / 新暗语 | 追加进 `09-违禁词与暗语替换表.md` 对应品类表（活表，随时补） |
| 新的品类视觉风格 / 配色 / 版式 | 追加进 `12-贴图尺寸与品类视觉方案.md`（给背景色+强调色+氛围+产品呈现+禁区），并在 `shot-template.html` 补一套 `.t-xxx` CSS 变量 |
| 平台尺寸 / 展示规则变化 | 更新 `12-贴图尺寸与品类视觉方案.md` 第一节（尺寸与安全区） |
| 某行业跑通的完整案例 | 追加进 `08-实战样本库.md`，标注：行业 + 象限 + 可复用点 |
| **业务场景判断 / 账号模型 / 团队配置 / 该不该上矩阵 / 老板要不要出镜** | 并入 `17-业务属性四场景与矩阵配置.md`（四场景速判 / 账号模型配置 / 矩阵三门禁 / 自检六问） |
| 平台治理数据更新（处置账号数、审核机制变化） | 更新 `06-矩阵运营与风控.md` 与 `09-违禁词与暗语替换表.md` 的验证结论 |
| 只是一条灵感、还没验证 | 先留在本目录，标注「待验证」，不并入正式 reference |

## 蒸馏的 6 个字段

1. **一句话**：这个方法解决什么问题
2. **什么时候用**：触发场景
3. **怎么干**：可执行的步骤或填空模板
4. **自检清单**：做完怎么验
5. **坑 / 反例**：怎么翻车
6. **实战样本**：一个填好的例子

## 铁律

- **没验证过的东西不写进正式 reference**，只留在 _inbox 标「待验证」
- 并入后必须同步更新 SKILL.md 的路由表，否则等于没加
- 不改已有规则来迁就新东西——新东西和旧规则冲突时，**报给用户定夺**
